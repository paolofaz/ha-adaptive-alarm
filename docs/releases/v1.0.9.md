# Adaptive Alarm v1.0.9 — quiet diagnostic notifications

This release prevents notification storms when Home Assistant or Zigbee2MQTT
restarts, without delaying any physical alarm or vibration notification.

- Protected sensors that temporarily become unknown/unavailable, and a
  configured lock that temporarily loses its locked reading, are not notified
  immediately. They must remain in a problematic state for **60 seconds**.
- The first **120 seconds** after the integration starts are silent for these
  *diagnostic* notices. Eligible faults are bundled for **10 seconds** into
  one message; the same persistent fault is not reported repeatedly.
  Subsequent batches are separated by **at least 5 minutes**.
- If a damaged stored session leaves the alarm in `FAULT`, one critical
  message is sent after the startup grace, rather than as a startup burst.
- Restarted deterrent-light ownership remains discarded for safety, but the
  restart only produces a consolidated notice if one of those lights is
  still confirmed ON after the startup grace.
- Adding an alternative group with an existing name now reports a validation
  error instead of silently replacing the previous group.

**Unchanged:** alarms on genuine openings, confirmed vibration events,
vibration prealerts, siren ON/OFF, alarm state recovery, HomeKit entities,
deterrent lighting controls and existing configuration.

Upgrade normally through HACS; restart Home Assistant. No reconfiguration is
necessary. The "sensor anomalies" notification switch must remain enabled
to receive persistent diagnostic/FAULT alerts. These checks are covered by
unit tests; the integration is not a substitute for a certified alarm.
