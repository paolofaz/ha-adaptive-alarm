# Adaptive Alarm v1.0.3 — Lovelace state icon and HACS publishing preparation

## Visual behavior

The bundled **`custom:adaptive-alarm-card`** uses a steady shield icon
during `disarmed`, `arming` and `armed_away`. Only an actual
`triggered` alarm makes the shield warning icon flash; the flashing
animation is disabled when the browser requests reduced motion.

The change applies **only to the bundled custom card**. The native Home
Assistant alarm panel may animate `arming` by its own design, and Apple
Casa controls its own user-interface animations. The Home Assistant
`alarm_control_panel` phase model is unchanged, preserving HomeKit and
automations.

## HACS publishing hygiene

- HACS Action now runs **without excluded checks**, including the GitHub
  repository topics check.
- HACS Action and Home Assistant hassfest remain required CI validations.
- Official GitHub Release publishing is now gated on successful integration
  validation **and** a second run of the core Python/JavaScript tests. It
  never publishes a release before these checks complete.
- Added HACS catalog submission checklist, contributing instructions,
  security policy and a redaction-friendly issue template.
- Maintained the single-integration `custom_components/adaptive_alarm`
  structure, a recognized MIT license, manifest, HACS JSON, user docs,
  translations, local icon, changelog and YAML dashboard compatibility.

## Installation

Upgrade via HACS to `v1.0.3`, then restart Home Assistant and reload the
existing Lovelace dashboard to refresh the JavaScript card.
If Lovelace **resources are managed via YAML**, update the module URL
in the existing `lovelace.resources` configuration to:

```yaml
- url: /adaptive_alarm/adaptive-alarm-card.js?v=1.0.3
  type: module
```

The card configuration is unchanged:

```yaml
- type: custom:adaptive-alarm-card
  title: Antifurto
```

## HACS default-directory submission status

The repository can already be installed as a **custom HACS repository**.
Default-directory inclusion has **not been requested or approved**. The
central `home-assistant/brands` registration, independent end-to-end
hardware testing and eventual owner-submitted PR to `hacs/default` are
tracked in [HACS publication readiness](../HACS_PUBLICATION.md).

## Safety

No changes were made to physical siren commands, HomeKit state reporting,
lock handling, vibration protection, RF, alarms or external automations.
Real siren output is still explicitly opt-in and depends on a verified
independent cutoff at the Zigbee device.
