# Adaptive Alarm v1.0.8 — Deterrent-light notification fix

## Fixed

When a vibration sensor produced a valid prealert and deterrent lights were
configured with automatic switch-off, the expiration routine sent an
unnecessary phone/Telegram notification **for each light** after the
configured delay. This was a notification bug, not a new vibration event.

Adaptive Alarm v1.0.8 removes those routine success messages. You now receive
the configured **vibration prealert**, without a second message for every
deterrent light that is automatically switched off.

## Preserved behaviour

- Deterrent lights still turn on and automatically turn off with the same
  configured delay and safety checks.
- Each deterrent_light_off_requested event remains available on the
  adaptive_alarm_event Home Assistant event bus for diagnostics.
- Genuine safety warnings (failed automatic OFF, skipped OFF because ownership
  cannot be confirmed, and unconfirmed light activation) still notify.
- Vibration confirmation, alarm triggering, siren output, sensor reporting,
  notification routing and Lovelace card behaviour are unchanged.

## Install and verify

Update to v1.0.8 through HACS and restart Home Assistant. Arm the alarm and
cause a single valid vibration prealert with multiple configured deterrent
lights. Confirm the vibration notification arrives once; after the configured
delay, verify the lights turn off **without an additional success notification
per light**. Use Developer Tools → Events and listen to adaptive_alarm_event
if you want to inspect each switch-off request.
