# Adaptive Alarm v1.0.5 — Lovelace storage resource fallback

## Fixed

Some installations use **Home Assistant-managed Lovelace resources** but
do not receive an automatic entry for the Adaptive Alarm JavaScript module.
v1.0.4 changed only the YAML-resource behavior and did not address this case.

In v1.0.5 the module is also registered directly with
`homeassistant.components.frontend.add_extra_js_url` in storage mode.
This means the card loads automatically even when the separate Lovelace
resource collection cannot be created or updated. The integration still
attempts to add/update the resource entry in Home Assistant's UI,
and logs actual errors when that operation fails.

This fallback may not produce a visible **Resources** list entry if HA's
storage collection rejects the operation; the reliable check is whether the
card itself renders on the existing dashboard.

### Usage

After updating and restarting Home Assistant, refresh your browser:

```yaml
- type: custom:adaptive-alarm-card
  title: Antifurto
```

You do not need to add a resource URL manually. The location of the card
on a YAML dashboard still belongs to the user; the integration never edits
their Lovelace layout.

If the card still does not load, search Settings → System → Logs for
`Adaptive Alarm card registration failed` and
`automatic Lovelace storage resource registration failed`. Share the
redacted traceback so that the exact runtime incompatibility can be fixed.

## Scope and testing

Adds behavioral tests for broken storage collection, normal storage updates
and missing Lovelace data. This change is limited to frontend loading.
The alarm state engine, Zigbee siren, HomeKit and notifications are unchanged.
