# Adaptive Alarm v1.0.4 — automatic Lovelace card loading

Fixes a missing automatic card module in installations that keep their
Lovelace **resources** under `lovelace: resource_mode: yaml`.

Before v1.0.4, the integration registered the bundled JavaScript card only
when Lovelace resources were stored in Home Assistant's UI. In YAML resource
mode it required a manual entry, even if Adaptive Alarm itself was installed
correctly.

**Now the module is loaded automatically in both modes.** In YAML resource
mode Adaptive Alarm calls Home Assistant's supported
`frontend.add_extra_js_url` API; in storage mode it maintains the existing
resource registration. It never rewrites YAML configuration or dashboards.

## Upgrade

Install v1.0.4 via HACS, restart Home Assistant, then hard refresh the
existing Lovelace dashboard. There is no longer a need to manually list
`/adaptive_alarm/adaptive-alarm-card.js` under `lovelace.resources`.

The card itself still needs one declaration **where you want it** inside
your YAML dashboard:

```yaml
- type: custom:adaptive-alarm-card
  title: Antifurto
```

If an earlier manual resource entry exists, remove it after verifying the
automatic module loads, avoiding duplicate registration.

A resource loaded through the frontend API does not necessarily appear
in the Lovelace Resources list. Its presence can be confirmed by the
working `custom:adaptive-alarm-card` in the dashboard.

No changes to alarm protection, `siren.*`, Zigbee2MQTT, HomeKit or automation
behavior. Real siren output remains separately enabled and requires its
independent hardware cutoff.
