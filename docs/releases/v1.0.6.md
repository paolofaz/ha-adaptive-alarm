# Adaptive Alarm v1.0.6 — Lovelace editor and siren startup

## What changed

The **single-card editor** in Home Assistant expects a YAML mapping:

```yaml
type: custom:adaptive-alarm-card
title: Antifurto
```

Do **not** add a leading dash (`- type:`) in that editor. The dash is
correct only under the dashboard's parent `cards:` list. This mistake
causes Home Assistant's "No card type configured" message and may trigger
an undefined `startsWith` error. The card now also rejects invalid
config objects with a more actionable message.

**Zigbee2MQTT siren startup:** Home Assistant frequently restores the alarm
integration before Z2M exposes the `siren.*` entity or service. Adaptive
Alarm used to log an error immediately when requesting startup OFF.
v1.0.6 defers that *initial* OFF while the siren is not yet available.
It retries automatically on the existing one-second tick and sends OFF when
the entity and service are ready. A device still unavailable after two
minutes emits a single warning and an event, while the pending OFF remains
queued. Real siren command failures outside startup retain error reporting;
physical siren ON is never automatically retried merely because it is
unavailable. This is designed to avoid spurious startup warnings while
preserving conservative shutdown behavior.

The physical siren still requires explicit opt-in and the Zigbee device's
independent auto-off setting. HomeKit and all protection logic remain
unchanged.

## Upgrade

Install from HACS, restart Home Assistant, hard-refresh your dashboard.
The card JavaScript resource is versioned `v=1.0.6` and is automatically
registered. No separate dashboard or manual resource YAML is required.
